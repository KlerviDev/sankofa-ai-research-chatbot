
# Contribution Guidelines – Sankofa

## 1. Branching Strategy

- `main`: The main and stable branch.
- `feature/feature-name`: For new features.
- `fix/issue-name`: For bug fixes.
- `docs/document-name`: For documentation updates.

## 2. Creating a Branch

Each team member must create their own branch from `main`.

Before starting work:

1. Pull the latest changes from `main`.
2. Create a new branch.
3. Work exclusively on that branch.

## 3. Pull Requests

Once a task is completed:

1. Push the branch to GitHub.
2. Open a Pull Request targeting `main`.
3. Provide a clear description of the changes made.
4. Wait for the review before merging.

## 4. Code Review

All Pull Requests must be reviewed before being merged into `main`.

Review comments and requested changes must be addressed or discussed with the author before merging.

## 5. General Rules

- Do not commit directly to `main`.
- Use clear and descriptive branch names.
- Write meaningful commit messages.
- Link every contribution to a Trello card.
